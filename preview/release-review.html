01URLs, redirects and SEO

Cause of the Google 404. Vercel matches routes strictly, and the rewrite /:locale/:path* does not match /ar/ (an empty trailing segment). Live /ar/ therefore fell through to a 404, and so did every /<locale>/ root Google had indexed.

Fix. Public URLs are now clean: /<locale>/…. The former /preview/<locale>/… URLs permanently redirect (308, which Google treats like 301) to the matching clean URL, project paths included. Unrelated missing URLs still return 404; they are not sent to the homepage.

02Google Search Console, after deploy

  1. Open Search Console for hashemkayyali.com (Domain property, or URL-prefix property for https://hashemkayyali.com/).
  2. Sitemaps → submit https://hashemkayyali.com/sitemap.xml. If an older sitemap with /preview/ URLs is listed, remove it.
  3. URL Inspection → https://hashemkayyali.com/ar/ → Test live URL. It should say “URL is available to Google”. Then Request indexing. Repeat for /en/ and one project page.
  4. Inspect an old URL such as https://hashemkayyali.com/preview/ar/: it should report “Page with redirect”. That status is expected, not an error.
  5. Pages report → “Not found (404)” → Validate fix once the live checks pass.

Google decides when it recrawls. Results usually move over days to a few weeks; requesting indexing does not guarantee timing or ranking. The old /preview/ URLs will drop out as Google follows the redirects.

08Project image flight

Cause. The flying image was an upscaled bitmap (blur), and the empty destination frame showed behind it. The flight now lays the image out at its destination size and scales it down to the source (no resampling at the end), follows the visible image rectangle (including letterboxing), interpolates the corner radius, and hides the destination frame chrome during the flight.
